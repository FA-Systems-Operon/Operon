## Confirmed scope and implementation decisions

1. Mandatory fields: business number, website, domain platform, Meta Business Manager account, Facebook Page, Instagram, phone number, email, and business address. Extend extraction and source references to those nine nullable text fields. Name, needs, and goals remain supported but are not mandatory. Business number and domain platform retain source-backed text without restrictive format validation.
2. Check the combined profile: information supported by either source is sufficient. Missing values stay null. A field with unresolved competing values is conflicting rather than missing.
3. Use deterministic missing checks plus AI-proposed potential conflicts with both source quotes. Validate evidence and document kinds in code. Neither source automatically wins; preserve both alternatives.
4. Extend the existing DraftSourceView component; full review page integration remains #57.
5. Add deterministic automated acceptance tests and a small real-model evaluation, recording unavailable evaluation as pending.

Approval blocking and conflict resolution are dependencies for Epic 4, not silently added to these issues. The architecture requires them eventually; these issues alone cannot establish that unresolved drafts are safe to approve. Do not mark parent story stakeholder sign-off complete automatically.

## Proposed data and behavior contract

- Retain `name`, `needs`, `goals`, and `source_references` and existing field paths. Add the nine mandatory scalar fields as nullable text with defaults for old payloads.
- Add a typed assessment (`rules_version`, `missing_fields`) and a separate typed `conflicts` list to the version's existing JSON data. This distinguishes an assessed draft with zero flags from a legacy draft that was never assessed. The contract is mirrored in TypeScript.
- Missing entries identify mandatory scalar fields. Conflicts identify a field and explanation, targeting scalar fields, needs/goals groups, or existing `needs/N` / `goals/N` items.
- Each conflict preserves exactly two competing interpretations, each with its value, document ID, and exact source quote. Require evidence from distinct transcript and intake documents. Use stored kinds, never client/model claims about document kinds.
- Keep a conflicted displayed value explicitly provisional. Preserve both alternatives without selecting an authoritative winner, changing approval status, or silently reconciling the disagreement.
- A different list item, added detail, or differently worded equivalent statement is not automatically a conflict. The prompt must identify incompatible claims about the same subject and context. Ambiguous cases need reviewer judgment and must not be presented as proven contradictions.
- Missing flags are computed by code from the agreed required-field policy, not accepted as authoritative model assertions. Missing facts remain null/empty; do not invent evidence for absence.
- Validate canonical field paths, nonblank values/explanations/quotes, evidence ownership, exact quote membership, and duplicate flags. Invalid model evidence fails the job without persisting a partial draft; invalid API evidence returns the existing 422 response style.
- Legacy versions remain unchanged and render as not assessed. No database migration is expected because version data is already JSON. Generic profile edits must not gain an implied verified-assessment guarantee; document this boundary and coordinate recomputation/invalidation with the future edit flow.
- Quote verification proves provenance, not semantic correctness or detection completeness. Explain this in documentation and validation evidence.

## #43 — Detect and persist flags

1. Freeze the contract and controlled examples using the confirmed product decisions above.
2. Extend strict Pydantic models in `backend/src/ai/source_prompt.py` (or a small focused sibling module). Separate raw model conflict proposals from the server-computed assessment so the model cannot mark its own validation complete.
3. Extend the existing prompt to compare transcript/intake claims, preserve both values and quotes, and avoid false conflicts caused by paraphrases or complementary information. Retain the current provider interface and untrusted-document instructions. Do not modify the separate Epic 2 evaluation prompt.
4. Add pure assessment/validation helpers, preferably in `backend/src/profile_flags.py`, for missing rules, path checks, and evidence validation. Keep network and persistence out of these helpers.
5. Integrate assessment into generation and `save_source_profile`. Load the union of documents used by ordinary references and conflict evidence, check client ownership, and validate actual document kinds. Today the save function substitutes `kind="transcript"`; replace that assumption where kind matters, while preserving compatibility for old ordinary references without conflict evidence.
6. Ensure generation remains pinned to the job's exact source pair. The direct source-draft endpoint validates against supplied evidence and stored client documents; it must not claim comparison of unprovided documents.
7. Persist values, references, and assessment in one immutable version and the existing job transaction. Ensure validation results are actually saved: the current save path calls the parser for validation but ignores its return value.
8. Preserve job retry/lease behavior. Validation failures follow the existing failure path, with no partial version and no raw source text in user-facing errors. Schema-constrained generation may make one controlled repair call for invalid output, as required by the architecture. Both attempts use the same strict validator; the job retry/lease policy is unchanged.
9. Update backend documentation with the schema, missing policy, legacy behavior, and limitations.

Tests delivered with #43:

- Each of the nine mandatory fields missing or supplied by either source, and complete profile; blank extracted strings remain invalid.
- Valid conflict retaining both alternatives, ordinary references, and source kinds.
- Invalid field paths, nonexistent list items, duplicate flags, invented quotes, wrong document kinds, same-document evidence, and another client's documents.
- API save/read round trip; unchanged old versions and approval metadata; atomic rejection without a new version.
- Job generation with assessment, validation failure without a draft, and existing retry/recovery regressions.
- Old payload compatibility without interpreting absent assessment as a clean result.

Done when the job and source-draft save path persist validated assessments, negative cases fail safely, and existing source/profile/job suites pass.

## #44 — Show flags in the draft view

1. Extend `frontend/src/components/draftSources.ts` to mirror the agreed contract with explicit TypeScript types and backward-compatible reads.
2. Extend `DraftSourceView.tsx` to render missing warnings even when a group has no rows. Put item-level conflicts by the affected item and group-level conflicts by the group heading without duplicating them across rows.
3. Show text labels such as “Missing information” and “Potential conflict,” a short explanation, and both competing values/quotes with links through the existing `getSourceHref` callback.
4. Use accessible semantic markup and visible text rather than color alone. Keep source links keyboard accessible; render source/model text as ordinary React text, not raw HTML.
5. Preserve existing value/source rendering. Legacy drafts show that checks are unavailable; malformed or unknown flag paths must not crash the view or become a misleading “no conflicts” result.
6. Document the props and integration point for #57. No new full review page, navigation, editing, resolution, or approval controls are included in the recommended scope.

Tests delivered with #44:

- Missing groups, item and group conflicts, multiple flags, both evidence links, and unflagged assessed drafts.
- Legacy drafts, unsupported paths, escaped text, and existing source-link regressions.
- Accessibility-oriented queries for warning labels and links; manual keyboard/visual inspection using a controlled component preview.

Done when every valid persisted flag appears beside the intended field/group, both alternatives remain visible, and frontend tests and build pass.
